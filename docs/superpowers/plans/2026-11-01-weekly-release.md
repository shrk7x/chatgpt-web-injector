# Weekly Release Implementation Plan

Goal: Automatically publish pending features and fixes once a week, on Monday at
09:00 America/Denver. Weeks without releasable changes create no new version.

Architecture: Keep push-triggered release-please updates. On the weekly schedule,
refresh the release PR, test its exact head, squash merge it with an expected SHA,
then run release-please again in the same workflow to create the release. This
avoids relying on a push event generated by GITHUB_TOKEN. Package the release tag,
not the triggering workflow commit. Existing store publishing remains unchanged.

Alternatives: Per-PR publication updates too often; a separate external scheduler
adds credentials and coordination. Extend the existing workflow instead.

Constraints: No new extension permissions or runtime dependencies. Preserve
manual release and store retry. No direct publication while implementing this PR.
